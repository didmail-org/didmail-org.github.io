01 / THE IDEA

A different foundation
for a familiar thing.

The inbox feels familiar. The foundations give identity and encrypted content a different place to live.

01

Start with your identity.

Create or import a DID wallet. Your identity is based on cryptographic keys, rather than an account created by a mail provider.

↗
02

Seal it before sending.

Message content and attachments are encrypted on the client. Mail nodes store encrypted content; privacy still depends on key security and the surrounding system.

⌁
03

Build on open foundations.

The project uses Apache-2.0 for original code and documentation. Protocol drafts and shared compatibility fixtures help the clients evolve together.

A FEW THINGS TO KNOW

Before you
jump in.

Where can I get the apps?＋

Public downloads are being prepared. The GitHub organization is the project’s current public entry point; release and contribution information will be added as it becomes available.

Can I run a mail node?＋

DIDMail includes a node server and administration dashboard. Deployment documentation and hosted-runtime acceptance are still evolving. Instructions will accompany the public source release.

What does the license allow?＋

Apache-2.0 permits commercial use, modification, and redistribution subject to its terms. Third-party components retain their original licenses. Read the license ↗

Does encryption hide everything?＋

End-to-end encryption protects message content. It does not automatically hide all metadata, protect a compromised device, or replace secure key management. DIDMail remains a development project.
